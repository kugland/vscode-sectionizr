# Sectionizr

Inserts comment section banners into source files. This is a port of
[kugland/sectionizr](https://github.com/kugland/sectionizr), a plugin for
Sublime Text, to VS Code.

## Examples

Both examples below are the real output at ruler 80, generated by calling
`render()` from `src/format.ts` directly (not hand-drawn).

Level 0 — a boxed, three-line banner with the title centered and uppercased:

```python
###############################################################################
#                               DATABASE HELPERS                              #
###############################################################################
```

Level 1 — a single line with the title centered in fill characters, case
preserved:

```python
############################### Database Helpers ##############################
```

An empty or whitespace-only line renders a plain divider instead of a titled
banner:

```python
###############################################################################
```

The comment tokens change per language. In a JavaScript/TypeScript-family
file the same level 0 banner looks like this:

```javascript
///////////////////////////////////////////////////////////////////////////////
//                              DATABASE HELPERS                             //
///////////////////////////////////////////////////////////////////////////////
```

## Usage

| Command | Keybinding | Mac |
| --- | --- | --- |
| Sectionizr: Create Section (Level 0) | `ctrl+k 0` | `cmd+k 0` |
| Sectionizr: Create Section (Level 1) | `ctrl+k 1` | `cmd+k 1` |

Both commands are also available from the Command Palette under those same
titles. Keybindings are active whenever an editor has focus and is not
read-only.

Type a title, put the cursor on that line (or select it), and run the
command. If you select multiple lines, they collapse into a single banner:
each line is trimmed, blank lines are dropped, and what remains is joined
with single spaces to form the title. The indent of the inserted banner comes
from the first selected line.

Multiple cursors each produce their own banner, and all of them are applied
as one undo step — a single `ctrl+z` removes everything the command inserted.

## Settings

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `sectionizr.formats` | object | `{}` | Comment tokens per language id, merged over the built-in table. |
| `sectionizr.uppercaseLevel0` | boolean | `true` | Uppercase the title in level 0 banners. |
| `sectionizr.blankLines` | boolean | `true` | Surround the inserted banner with blank lines. |

`sectionizr.formats` overrides or adds languages. Each entry needs a
`prefix`, a `fill` (exactly one character), and a `suffix`; none of the three
may contain control characters. A malformed override is ignored for that
language, falling back to the built-in format rather than breaking the
command.

```jsonc
"sectionizr.formats": {
  "rust": { "prefix": "//", "fill": "/", "suffix": "//" }
}
```

Built-in coverage, by comment style:

- `#` — Python, Ruby, Shell Script, Perl, Makefile, PowerShell, R, YAML,
  TOML, Dockerfile, Nix, Elixir, Julia
- `//` — JavaScript(/React), TypeScript(/React), JSON(C), Java, C++, C#,
  Objective-C(++), PHP, Sass, SCSS, Less, Go, Rust, Swift, Kotlin, Scala,
  Dart, Zig, Groovy
- `/* */` — C, CSS
- `--` — SQL, Haskell, Lua
- `%` — TeX, LaTeX, BibTeX, LilyPond
- `<!-- -->` — HTML, XML, XSL, Markdown, Vue, Svelte

An unsupported language shows a warning naming the language id and makes no
edit.

## How the width is chosen

Sectionizr picks a target column in this order:

1. The smallest entry in `editor.rulers`.
2. If there are no rulers, `editor.wordWrapColumn`.
3. If neither is set, 80.

Banners are rendered one column short of that target, by design — this is
inherited from the original Sublime Text plugin, and it keeps the ruler
visible just past the banner's right edge instead of sitting on top of it.

## Differences from the Sublime version

- **Keybindings are two-keystroke chords, not three.** VS Code's default
  keybinding editor doesn't expose a clean way to bind a three-key chord like
  `ctrl+k c 0`, so section levels are bound to `ctrl+k 0` and `ctrl+k 1`
  directly. `ctrl+k ctrl+0` was not used because it's VS Code's built-in Fold
  All command; that's also why these are plain digits rather than
  `ctrl`-chorded ones.
- **Language matching uses VS Code language ids**, not TextMate scopes. The
  built-in table above is keyed by language id (e.g. `python`,
  `typescriptreact`), so a language extension that assigns a different id
  than you expect won't be recognized without a `sectionizr.formats` entry.
- **A multi-line selection folds every non-blank line into one banner's
  title**, joined with spaces. The original only ever used the first
  selected line's text and silently discarded the rest of the selection;
  this port preserves all of it — see Usage above.
- **An empty line collapses to a single divider line**, not the full banner
  shape with a blank title row that the original still produced even when
  the selection was empty.
- **Full-width (CJK) characters are not accounted for in the centering
  math.** Centering counts UTF-16 code units, not display columns, so a
  title containing CJK characters will be visibly off-center. This is a
  known limitation, not a bug to be filed against this specific behavior.

## Development

- `npm test` runs the fast unit suite (Vitest).
- `npm run test:integration` runs the VS Code integration suite. This
  requires a display capable of giving a real window focus. The single-undo
  test is a known environmental failure on headless hosts or hosts without a
  window manager — including bare Xvfb with no WM running — because VS Code
  needs real focus semantics to coalesce edits into one undo step there. This
  is not a product bug; it's a property of the test environment.
